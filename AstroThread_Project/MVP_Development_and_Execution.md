# AstroThread – Sprint Plan

## 1. Sprint Goal

The goal is to organize AstroThread MVP development into manageable sprints, prioritize features, assign responsibilities, identify dependencies, and define completion criteria.

## 2. Sprint Duration

- Sprint 1: 5 days
- Sprint 2: 5 days

The schedule can be adjusted according to team progress and the project deadline.

## 3. Team Members and Responsibilities

| Team Member | Responsibilities |
|---|---|
| Alaa | Backend Development and Frontend Development |
| Bothaina | Backend Development and Database Development |
| Dana | Frontend Development and Database Development |

All team members will collaborate on integration, testing, code reviews, and completing the MVP.

## 4. Sprint 1 – Core Features

**Goal:** Set up the project and implement the basic research browsing functionality.

| Task | Priority | Responsible | Dependency |
|---|---|---|---|
| Set up frontend, backend, and database | Must Have | All Team Members | None |
| Implement user registration and login | Must Have | Alaa and Bothaina | Database setup |
| Display and search research threads | Must Have | Alaa and Dana | Project setup |
| Display thread details and related research papers | Must Have | Alaa and Dana | Research threads |
| Implement database models and API endpoints | Must Have | Bothaina and Alaa | Database setup |
| Test completed features and fix bugs | Must Have | All Team Members | Implemented features |
| Review and integrate code changes | Must Have | All Team Members | Code changes |

## 6. MoSCoW Prioritization

### Must Have
- User registration and login.
- Browsing and searching research threads.
- Thread details and related research papers.
- Discovery timelines.
- NASA images and data.
- Interactive data visualizations.
- AI research assistant.

### Should Have
- Bookmarks.
- Profile management and password changes.
- Owner Dashboard for creating, editing, and deleting research threads.

### Could Have
- Premium subscription plans.
- Demo activation for Premium features and increased AI usage limits.

### Won't Have in This MVP
- Real payment processing.
- Advanced physics simulations.
- Other features planned for future releases.

## 7. Definition of Done

A task is considered complete when:

- The feature works according to its requirements.
- The code is reviewed and follows project standards.
- Relevant tests are performed.
- Identified bugs are fixed or documented.
- Changes are committed and pushed to the GitHub repository.

## 8. Sprint Tracking

The team will review task progress regularly, discuss blockers, and update the sprint plan when necessary. At the end of each sprint, the team will review completed work and identify improvements for the next sprint.

## 9. Dependencies and Risks

- Frontend integration depends on the availability of backend API endpoints.
- Backend features that use stored data depend on database models and configuration.
- NASA and AI features depend on external API availability and configuration.
- Integration testing depends on the completion of the relevant features.

The team will prioritize core features and adjust the schedule if technical issues or time constraints arise.
